## 1. 审计范围与取证方法

- **范围**：6 个子系统——数据层、训练引擎与任务面、推理运行时与跟踪、
  导出与模型注册表、服务面（serving + CLI）、指标与合规。
- **方法**：每个子系统独立深审（设计/流程/缺陷/异常场景四个维度），
  约 15 个关键缺陷经运行时实证复现（构造最小输入触发实际错误），
  非静态推断。
- **门禁取证**（2026-11-06 本机，全部通过）：
  `ruff check src tests scripts` 全绿；
  `scripts/check_layering.py` / `scripts/check_provenance.py` 通过；
  `mkdocs build --strict` 零警告；
  AGENTS.md §5 两组目标测试 110 + 141 = 251 个全部通过。
  另发现 AGENTS.md §5 文档中的 mypy 命令对
  `src/autovision/inference/stream.py:512` 报一个类型错误
  （`LineZone` 变量被赋值 `PolygonZone`）——CI 的 mypy 文件清单不含该
  文件，故 CI 绿但文档承诺的本地检查是红的，见 §7。

## 2. 总体判定

审计结论：**工程骨架达到企业级上游水准，但当前状态不能一次性通过企业级
验收**。共发现 12 个 P1（正确性/功能可用性，其中多个经运行时复现）、
约 36 个 P2、约 80 个 P3。差距集中且可收敛：完成本文档组的 P1 全部与
关键 P2 后，大部分模块可达到验收标准。

| 子系统 | 设计质量 | 验收判定 | P1 | P2 | 文档 |
|---|---|---|---|---|---|
| 训练引擎与任务面 | 优秀 | 核心路径达标，修 4 个 P2 后整体达标 | 0 | 4 | [训练引擎与任务面](training_engine.md) |
| 导出与模型注册表 | 优秀 | 优秀工程库，修 1 P1 + 关键 P2 后可验收 | 1 | 9 | [导出与模型注册表](export_registry.md) |
| 推理运行时与跟踪 | 良好 | 有条件通过（修 1 P1 + 2 P2 后可验收） | 1 | 5 | [推理运行时与跟踪](inference_runtime.md) |
| 服务面（serving + CLI） | 良好 | 受控环境可用；对外生产需先修 2 P1 | 2 | 5 | [服务面](serving_surface.md) |
| 数据层 | 热路径良好 / 版本化有硬伤 | 部分达标 | 4 | 8 | [数据层](data_layer.md) |
| 指标与合规 | 骨架好，口径有硬伤 | 未达标——对外指标数字失真 | 4 | 5 | [指标与合规](metrics_compliance.md) |

最严重的四类问题（按对企业验收的威胁排序）：

1. **对外指标数字不可信**（METRIC-01/02/03/04）：OBB AP 两处正确性
   bug（一虚高一虚低、叠加后读数不可预测）、crowd 标志训练链路断链、
   headline P/R/F1 口径与披露文案双重失真。
2. **数据管理功能对常见格式不可用**（DATA-01/02/03）：版本化快照对
   标准 YOLO data.yaml 完全不可用且校验对新增 split 失明；YOLO mmap
   行缓存对图像增删不失效——"数据钉版"卖点在 YOLO 上不成立。
3. **变更型操作的状态一致性**（EXPORT-01、SERVE-01）：模型注册表
   注册/晋升中途被杀会永久卡死该版本；registry CLI 先变更后校验。
4. **长时运行的单点失败放大**（INFER-01/03）：多路流单一源渲染失败
   终止全局并丢 summary；单路流一帧 NaN 即终止 24/7 长跑。

## 3. 编号体系与文档组导航

- 每个子系统的发现按 `模块前缀-序号` 编号：`DATA-nn`（数据层）、
  `TRAIN-nn`（训练）、`INFER-nn`（推理）、`EXPORT-nn`（导出/注册表）、
  `SERVE-nn`（服务面）、`METRIC-nn`（指标/合规）。序号在各文档内
  连续，P1 在前、P2 次之、P3 收尾。
- 本编号体系刻意避开加固计划的 `D<n>` / `H<n>-<m>` 语法——后者由
  CI 的设计锚点检查强制"每个编号必须被至少一条测试引用"（见加固计划
  H4-3）。本组编号是审计跟踪号，不进该检查。
- 各文档中引用加固计划已有编号（如 H1-11、H3-2a、D17、D32）时，
  均指该计划中已实施或已排期的条目。

## 5. 横切模式（跨模块系统性问题）

四个模式横跨多个子系统，修复时应作为一致性清单逐条核对：

1. **"同一类错误、不同入口、宽严不一"**：丢未知类别（COCO 计数告警
   vs YOLO 静默，DATA-07）、重复 image_id（检测报错 vs 实例分割静默
   覆盖，DATA-08）、mask 宽松（`open_mask` 报错 vs 语义分割静默取
   channel 0）、NaN（JSON/渲染容忍 vs tracker 一帧即死，INFER-03）、
   sha 记忆化（downloadable 有 vs 模型注册表无，EXPORT-04）。
   整改原则：加固轮次按模块推进留下的横向不一致，按
   "损坏输入要么大声失败要么显式计数告警"统一收口。
2. **错误类型双轨制**：`src/autovision/errors.py` 有完整
   `AutoVisionError` 家族，但 `src/autovision/data/convert.py`、
   `src/autovision/cli/common_helpers.py`、导出热路径大量裸
   `ValueError`，调用方无法用单一 `except AutoVisionError` 收口
   （DATA-19、SERVE-12）。
3. **原子写纪律有六处漏洞**：pretrain 导出（TRAIN-02）、
   `best_metric.json` sidecar（TRAIN-04）、convert 输出（DATA-17）、
   合规报告（METRIC-18）、"工件 + sidecar"非同一事务（EXPORT-09）、
   注册表被杀残留（EXPORT-01）。骨架纪律很好（tmp + fsync +
   `os.replace` 遍布且有 SIGKILL/ENOSPC 注入测试），但这六处未贯通。
4. **负向/边界测试缺口是所有 P1 的共同漏网原因**：OBB 只有 AP=1/0
   两个退化点测试（METRIC-01/02）、serving 只有 TestClient 层、
   registry CLI 变更顺序无测试（SERVE-01）、crowd 无端到端 wiring
   测试（METRIC-03）。**每个 P1 都对应一个"未测试的行为"**——
   本文档组每项修复设计都强制要求补负向测试。

## 6. 整改路线（三阶段）

| 阶段 | 内容 | 涉及编号 | 出口标准 |
|---|---|---|---|
| 阶段 1：正确性 | 让对外数字与训练数据可信 | METRIC-01..04、METRIC-05、DATA-06/07 | OBB 有对拍金标准；crowd 端到端测试；headline 口径修正或如实披露；合规 CLI fail-closed |
| 阶段 2：功能可用性 | 数据钉版与训练规模可用 | DATA-01..04、EXPORT-01、INFER-01 | YOLO data.yaml 快照/校验可用；YOLO 缓存正确失效；实例分割内存受控；注册表可自愈；多路流隔离 |
| 阶段 3：状态一致性与长时可用 | 生产姿态收口 | SERVE-01..07、INFER-02..06、TRAIN-01..04、EXPORT-02..10、DATA-05/08..12 | 各模块文档 §验收标准 全部满足 |

每阶段合并前的回归门禁沿用加固计划 §10 的命令集
（ruff / mypy 触达模块 / 目标回归 / 全量测试 / provenance /
layering / docs links / mkdocs --strict），外加：

- 涉及数值行为的修复必须附对拍或金标准锚定（AGENTS.md §3.3 纪律）；
- 行为变更与弃用按 [发布流程](../release_process.md) 与
  AGENTS.md §3.4 处理，CHANGELOG 按节归位。

## 8. 企业级验收判定标准（本组文档的 DoD）

判定为"通过企业级验收"需同时满足：

1. 本文 12 个 P1 全部关闭，且每项带最小失败用例（修复前失败）+
   回归测试 + CHANGELOG 条目；
2. 阶段 1/2 列出的关键 P2 关闭（各模块文档 §验收标准 明确）；
3. 横切模式 §5 的 1/3 项在触达模块内收口（不要求全仓一次到位，
   但触达路径不得再引入不一致）；
4. 全量门禁绿（含双 Python 版本 CI），`known_limits.md` 与
   行为变更同步改写；
5. P3 清单（各模块文档末表）进入 0.7.x 批次排期，允许未修复但
   不得未登记。
