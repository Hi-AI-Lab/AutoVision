## 2. 与基线的有意差异（本轮新增）

| 决策 | 基线做法 | VTrain 做法 | 理由 |
|---|---|---|---|
| NT-Xent 负样本域 | LightlySSL `gather_distributed` 跨 rank 收集 | per-rank | 与蒸馏队列的 per-rank 语义一致，省一次 all_gather；小 batch 下有效负样本少，文档已声明 |
| DINO head 权重归一化 | `torch.nn.utils.weight_norm` | 手写 `_WeightNormLinear`（显式 g/v 参数） | torch≥2 的 legacy weight_norm 产生非叶子张量，`copy.deepcopy`（教师复制）直接崩溃；parametrizations 版不暴露 `weight_g` 属性 |
| DDP 验证指标 | Lightning 全量回传 | 指标状态对象 pickle 汇聚 | 与自研引擎对齐；状态（tensor 列表/混淆矩阵）天然可并加 |
| 任务 `watch_metric` | `get_watch_metric_mode` 按名推断 | `TrainModel.watch_metric` ClassVar 显式声明 | 「同名不同规」在编译期可见，配合协议指纹（§8.5）扩展 |
| timm/SG 测试门控 | CI 全量装依赖 | `importorskip` + `AUTOVISION_HF_TESTS` 门控下载 | extras 惰性策略下，套件不得被重依赖绑架 |

0c. **【P0×2，VisDrone 收敛验证第二轮发现并修复】检测骨干网与基线存在三处结构性偏差，累计导致 mAP50 恒零**：(1) `loss_boxes` GIoU 全矩阵求和（见 0）；(2) 简化版解码器**缺失 encoder proposal 机制**——真 RT-DETR 由 `input_proj → grid anchor 先验(0.05×2^lvl) → enc_score/enc_bbox 头 → top-k 选择` 产生 query（起点即在目标附近），简化版改用 `uniform(0.05,0.95)` 随机巨框 Embedding，对平均 0.022×0.039 的 VisDrone 小目标需自噪声框硬缩 30 倍，实测 2000 步匹配 IoU 停在 anchor 随机水平；(3) 简化版 HybridEncoder **缺失 AIFI 语义注意力与 CSPRepLayer/RepVgg CCFF**，decoder 读到的特征无判别力——过拟合测试（8 图 × 400 步专项训练）成为决定性判据：简化版 IoU 卡 0.084、`dec_bbox_head` 权重随机游走（梯度符号无一致性），完整 AIFI 版 IoU>0.5 占比 0.6%→17.5% 且 dn_giou 0.69→0.44 持续下降。同步修复：完整移植基线 `rtdetrv2_decoder.py`（823 行）与 `hybrid_encoder.py`（448 行）；CDN 噪声幅度补回 ×0.5；`num_top_queries` 100→300；lr 对齐基线 5e-4。0b. **【已实现】CDN 对比去噪 + 配方对齐（VisDrone 收敛验证第二轮的产出）**：`object_detection_components/denoising.py`（`get_contrastive_denoising_training_group` + `get_cdn_matched_indices`，正负双 query、标签/框加噪、分组注意力掩码）+ decoder 接线（`denoising_class_embed`、dn 组拼接与逐层切分、self-attn 的 attn_mask）+ criterion 的对齐去噪损失（`_dn_{i}` 后缀、`num_boxes × num_group` 归一化）。配方对齐基线：`lr 5e-4`（原 1e-4）、`backbone_lr_factor 0.05`、`num_top_queries 300`（原 100，密集数据 recall 上限）。评审修复：框噪声幅度缺 ×0.5（P0，正样本框可退化）、`padding_idx`、`reduce_dict` 跨 rank 键集并集（DDP 下 dn 键集合随批内 GT 有无而变化的隐患）。测试 `test_denoising.py` ×17。遗留偏差（有意，文档化）：dn query 的位置嵌入用类别嵌入而非基线的框驱动 `query_pos_head`——空间信息经由 deformable reference points 进入，若早期收敛仍不及基线，此项为第一嫌疑。

## 4. 超大件实现蓝图（M4+ 排期依据）

### 4.1 EOMT 分割家族（实例/语义/全景 × DINOv2/DINOv3）

基线结构（每任务一包，`_task_models/{dinov2,dinov3}_eomt_{instance,panoptic,semantic}_segmentation/`，共享 `_task_models/eomt/`）：

- **核心**：EOMT = ViT 骨干 + query 交互 transformer 解码器 + mask 分类头；掩码由 patch 级特征 × query 点积上采样合成。**策略转向（批次3）**：HF transformers 5.17.0 已收录 `eomt` 模型族（`EomtForUniversalSegmentation`/`EomtHungarianMatcher`/`EomtLoss`——focal+dice、grid_sample 归一化坐标采样点使 pred/target 尺寸解耦），蓝图中自建件（mask_loss/scale_block/matcher/hooks）由 HF 原生实现替代，共享包聚焦包装与任务胶水。
- **【已实现（批次3）】共享包**（`_task_models/eomt/`）：`modeling.py`（`build_eomt_model` 配置驱动构建 + `load_weights` from_pretrained + `adapt_eomt_head` 类头/query 迁移重建）、`labels.py`（`semantic_masks_to_instances` 类索引图→per-class binary 实例）、`postprocess.py`（语义 einsum decode + 实例 query decode，均 bilinear resize 回原图）、`scheduler.py`（AdamW + layer-wise lr decay 0.9^N，no-wd=bias/norm/layer-scale lambda）、`transforms.py`（scale-jitter 裁剪 + pad(ignore_index) + flip 的掩码联合几何）。
